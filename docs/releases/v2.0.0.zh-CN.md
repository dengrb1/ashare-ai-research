# A 股 AI 自动投研系统 v2.0.0

## 一次重大跃迁

v2.0.0 不是一次常规功能累加，而是项目从单点投研能力迈向可持续运行、可观测、可配置的完整研究工作台的一次重大跃迁。新版本贯通了 AI 问答上下文、收盘后研究、持仓监控、系统配置、任务隔离、行情状态和报告解释，并进一步强化了时点安全、审计与失败处理。

系统边界保持不变：本项目只服务于研究、事件驱动回测和模拟组合，不提供自动实盘下单，也不构成投资建议。

## 核心升级

- AI 股票问答新增持久化上下文、缓存与成本治理，扩展联网检索、附件和个人档案能力，并改善模型不可用时的错误处理与可观测性。
- 新增持仓止损、买入监控、退出建议和风险通知链路，通知、建议与运行结果均保留审计信息。
- 新增系统配置中心，可管理运行时参数、模型设置和资源状态；敏感配置继续由服务端保护，不暴露到浏览器存储或普通日志。
- 将高负载行情刷新和研究任务进一步隔离，支持双研究 Worker 部署，并加强 Redis 租约、任务状态、重试和资源治理。
- 行情刷新、缓存和预取链路显著提速；Web 端现在能识别 A 股开闭市状态，在休市时提供一致提示并减少无效刷新。
- 候选股新增可追溯的行业名称，贯通采集、规范化、存储、API、报告和前端展示，同时继续执行 `decision_at` 与 `available_at` 的未来信息校验。
- 研究报告、资产、候选、组合、行情和财报检索页面完成协同升级，运行状态与失败原因更清晰。
- 默认策略配置升级到 `first_release.v3`，增加聊天缓存、止损、买入监控和通知保留策略；历史 v1/v2 配置继续保留用于结果回放。

## 数据库与部署

本版本数据库迁移前进到 Alembic `0022_candidate_industry_name`，涵盖聊天风险通知、行情刷新参数、模型缓存成本治理、运行记录、系统配置中心和候选行业名称等结构变化。

升级前请备份 PostgreSQL、Redis、lake、object-data 或外部对象存储中的重要数据。拉取 v2.0.0 后，使用显式 Compose 项目名重新构建并启动：

```powershell
docker compose -p ashare-ai-src -f compose.yaml up -d --build
docker compose -p ashare-ai-src -f compose.yaml ps
```

部署过程会执行既有迁移入口。自定义部署应先运行 `ashare-ai doctor`，再运行 `ashare-ai migrate`，确认 PostgreSQL 与 Redis 健康后启动 API 和 Worker。不要删除已有数据卷来完成升级。

## 兼容性说明

- 公开业务 API 继续位于 `/api/v1`，本版本以向后兼容的新增字段和端点为主；Web Cookie 会话与 App Bearer Token 流程继续分离。
- Python 包、API 服务和 Web 应用版本统一为 `2.0.0`。
- `first_release.v1` 与 `first_release.v2` 的语义没有被重写，历史 Manifest 和快照仍应按其原始配置哈希回放。
- 自定义集成若严格校验响应字段，应允许 `/api/v1/market/status` 的新增 `market_session` 字段及候选结果的行业名称字段。

## 发布定位

v2.0.0 将项目的重点从“功能可用”推进到“链路完整、运行可管、数据可追溯”。这次重大跃迁为后续移动客户端、长期任务运行和更严格的研究复现奠定了稳定契约，但所有交易建议仍仅用于模拟与研究。
