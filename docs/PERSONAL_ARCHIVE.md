# 个人档案格式 v1

## 安全封装

文件扩展名为 `.ashare`，开头是 `ASHARE-PERSONAL-ARCHIVE\n`，随后为一行 JSON 加密头和 AES-256-GCM 密文。密钥由用户一次性口令经 scrypt（`N=32768,r=8,p=1`）派生；随机 salt、nonce 位于加密头中，文件魔数和加密头作为 GCM AAD。服务器不持久化明文口令；异步任务期间只保留用服务端轮换密钥包装的临时密文。

解密后是 ZIP，必须包含：

- `manifest.json`：格式版本、源应用版本、Alembic revision、生成时间、每个文件的 SHA-256/字节数，以及服务端来源认证标签 `source_auth`。
- `domain/profile.json`：版本化领域数据。
- `objects/{sha256}`：必要的非图片不可变对象。

`source_auth` 使用当前 `PERSONAL_DATA_ENCRYPTION_KEYS` 的首个密钥做 HMAC-SHA256；导入端会尝试当前及轮换保留密钥。这样用户口令只能证明包未被不知道口令的第三方修改，服务端认证还会阻止普通用户自行构造正式评分、运行状态或 Manifest。跨部署迁移时，目标部署必须安全配置至少一个与源部署共有的轮换密钥；不得通过网页、档案或日志传递该密钥。

导入会拒绝重复路径、绝对路径、`..`、反斜杠路径、过多条目、过大解压体积、未在 manifest 声明的文件、哈希/字节数不符、来源认证失败、PIT 时点冲突以及任何伪装在 `objects/` 中的图片文件。图片检测覆盖 PNG/JPEG/GIF/WebP、BMP、TIFF、ICO/CUR、PSD、JPEG XL、AVIF/HEIC 和 SVG，并检查常见前导包装后的强签名。

## 包含范围

`profile.json` 包含当前用户的自选、模拟持仓、总资产、退出监控、研究偏好、AI 线程与文本消息、研究运行及审计、评分、候选、模拟组合、报告、Trade Plan、退出建议、回测和必要快照。导入时所有资源归属当前用户，不使用源账户身份或权限。

以下内容永不进入档案：

- `image/*`、聊天原图、缩略图、模型图片副本、图片 URI、Base64、文件名和内容哈希；
- 密码/密码哈希、角色、Cookie、Web/App 会话、access/refresh token、API Key 和模型密文；
- Redis 队列、AI 响应缓存、服务器文件路径和存储桶地址。

聊天消息的图片附件被替换为 `{"type":"IMAGE_NOT_EXPORTED"}`，导入不会为它创建空附件。

## 预览与合并

- 自选股取并集，保留当前排序，导入新项追加。
- 同代码持仓、总资产、退出监控和研究设置在预览中展示当前/导入值，默认保留当前值。
- 历史记录按源 ID 和规范化内容去重；ID 相同但内容不同时生成新 ID，并重映射内部引用。
- 预览为聊天线程/消息、研究运行、报告和回测分别返回新增、完全重复与内容冲突清单及规范化哈希。
- 应用数据和任务成功状态在单一数据库事务中提交；导入对象写入当前用户、当前导入任务的专属目录，校验、引用重映射、完整性检查或数据库提交失败时会整体回滚并清理该目录。

## 保留与运维

导出文件、导入源包和预览默认保留 24 小时。删除与到期清理会锁定任务记录；Worker 在写文件或提交导入前再次校验删除和到期状态。`PRIVATE_OBJECT_ROOT` 必须指向持久私有卷；`PERSONAL_DATA_ENCRYPTION_KEYS` 使用逗号分隔的 URL-safe Base64 编码 32 字节密钥，第一个用于新写入和来源认证，后续密钥用于读取轮换前任务与档案。
